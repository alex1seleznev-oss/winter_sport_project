# История БД и проверка восстановления

`history/` — архив 13 фактически применённых миграций проекта wmiypacyraepljalppub, полученный чтением supabase_migrations.schema_migrations. Номера не придуманы. Manifest содержит контрольные суммы исходного SQL. `scripts/check-migration-history.mjs` требует точного совпадения текста.

Это архив для воспроизводимости, а не инструкция повторно применить миграции к действующей базе. Ранние миграции открывали больше данных; применять их по одной к production нельзя. Полный порядок заканчивается ограничивающими RLS-политиками.

`proposed/review_receipts.sql` — отдельная новая защита. Пока она находится здесь, наличие файла НЕ означает применение в production. Создаёт закрытые квитанции проверки и функцию проверки неизменности предложения/календаря; не создаёт и не изменяет гонки. Состояние production-применения фиксируется отдельно после тестов.

CI запускает PostgreSQL17 без production-секретов. `tests/bootstrap.sql` имитирует только нужные нашей схеме контракты auth.uid/auth.users/storage.buckets и роли. Затем воспроизводятся все 13 миграций, проверяются RLS и защита новой квитанции. Выполняется pg_dump и pg_restore в другую БД, повторно проверяются данные, индексы/триггеры и права.

Это испытание восстановления схемы приложения с синтетическими строками, НЕ восстановление реального production-бэкапа и НЕ проверка хранения бинарных объектов Storage. Секреты, профили пользователей, черновики и production-данные не экспортируются в GitHub или Actions-артефакты. Для аварийного восстановления нужны отдельный защищённый бэкап данных, бэкап объектов, проверка hosted-конфигурации и регламент оператора.

Функции проверки работают SECURITY INVOKER, не повышают права. SHARE ROW EXCLUSIVE сериализует служебные записи в три таблицы на короткую транзакцию, оставляя обычное чтение доступным; lock_timeout=2s. Это сознательный компромисс для небольшого календаря. Вызывающий будущий applier должен проверять квитанцию и изменять данные В ОДНОЙ транзакции. Функция не обязывает произвольного администратора или сторонний старый скрипт использовать её.

Официальные основания: PostgreSQL17 Explicit Locking; Supabase RLS и Database Backups. См. историю PR для фактических результатов CI, а не делайте вывод об успехе по наличию файлов.
