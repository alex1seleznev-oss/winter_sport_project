# Public media watch — credential-free read-only collection

Reduced scope, distinct from issue13's blocked complete package: only eight fixed public GET URLs. No privateAPI/token handling, Supabase publisher, automatic approvals or old privileged handlers. Source errors remain errors. No fullarticle bodies, comments, membership lists or media files are uploaded.

Output: short title pointer(max12words/160chars), permalink, date/time precision, forwarded origin, topic heuristics, content/revision/raw-document hashes. Sensitive topics get a generic review label. Claims remain unverified even for officialSocial sources. Exact timestamps require an explicit zone; date-only or unzoned datetime can retain only the calendar date. Unrecognized formats are labelled unresolved, not replaced by fetch time. This corrects the first live test's INDEX_TIMESTAMP rejection on a media index without pretending that unknown time is now verified.

FourTelegram previews plus Sports.ru biathlon/skiing, its genericRSS and Skisport section index. RSS may parse successfully but contain no relevant winter-sport articles in its current20-itemwindow; that is different from parser failure. Each live source is parsed twice from the same bytes with changed fetch metadata; semantic revisions must remain stable. Canonical post IDs and origin links make reposts traceable, not independent confirmation. Media sources with broad skiing coverage can contain alpine/personal stories; irrelevant formats excluded, sensitive topics queued generically.

Scheduled GitHub workflow every6hours after merge. Permissions contents:read/actions:read, no source credentials or database secrets. The temporary GitHub token is scoped to downloading a previous artifact from the same repository/workflow/branch, never sent to media sites. Archive reading is bounded and reads only packet.json, without extracting arbitrary paths. Only trusted push/schedule/manual runs, not forkPR artifacts. A missing/expired/incompatible baseline resets comparison honestly. Retention3days is NOT long-term audit storage. New/mutated references are compared by source+URL+revision; absent preview items are not deleted records. A custom Telegram/push channel is not connected.

Artifacts are minimal public-source research references; repository visibility is public, so they must not contain private editorial decisions or full sensitive text. DatabaseQueue remains private and distinct. Automatic collection is NOT automatic Supabase ingestion: a separately authorized bounded operator intake is required. No productionwriter credentials configured by this release. User'sVKgroups remain awaiting authorized API connection, not declared parsed. See docs/VK-ACCESS.md for the access boundary; do not paste tokens in chat.

Actual counts, passed tests and source receipts are recorded in PR after successful execution. SourceHTTP200 alone is not verification. The old53FLGRproposals and blockedreviewDDL are untouched.
