# Public media watch — reduced read-only scope

This release is deliberately narrower than the previously blocked full media-intake package: no VK token or private API handling, no database publisher, no automatic approvals, no raw article bodies/media storage. Eight fixed public GET URLs; redirects, login interstitials and format errors do not pass as a successful empty import. Failure is recorded and leaves existing calendar data untouched. No connection to the disabled legacy writer or blocked review-schema migration.

Source output: bounded title pointer(max12words/160chars), public permalink, optional publisher-provided timestamp, forwarded origin, topic heuristics, text/revision/document hashes. Counters/fetch time excluded from revision. Health-sensitive text becomes a generic review label; no medical inference. Claims all remain unverified. Feed description/body/images are not republished. No model-generated facts. Matching reposts are not independent corroboration. Missing posts from a sliding window are not deletions/cancellations.

Workflow has contents:read, no secrets and no productionDBaccess. Every6hours after merge it produces a report artifact; this is NOT automatic insertion into Supabase. Artifact visibility follows the repository(accessible repository is public), so output contains minimal public-source references, not the private editorial queue. Artifacts retained3days; full sourceHTML is not uploaded. Repository/logs contain no user credentials. VK/Instagram/login-only sources are explicitly listed as notConnected rather than scraped through login/proxies.

The pure delta routine can compare snapshots, but cross-run durable baseline retrieval and deduplicated owner notifications are not yet connected in this initial version. No new messages does not trigger any custom chat notification; GitHub workflow failures remain visible. Official sports data must be independently verified against the correct document before any calendar mutation. Repeat monitoring alone does not verify a social claim.

Actual live counts and tested contracts go into the PR after execution, not inferred from source HTTP200 or test-file existence. Existing50Telegram references in privateSupabase remain separate from this public minimal feed snapshot. A scoped database importer with credentials configured outside chat remains a separate release gate.
