# Stage interface — design and release evidence

This refines the user's winter-night visual direction in actual Next.js components, not another generated screen. Stage header, four direction shortcuts, query-backed filters, dimensional graphic covers, explicit status, compact live programme preview and a main stage action. All stage dates/counts come from the public database. Graphic covers are abstract geometry, not photographs or maps. No fake federation logos, celebrity autographs or supposedly verified athlete portraits.

Design reference reviewed: pbakaus/impeccable, skill/reference/craft-floor.md, blob d7a3aecc7d091c260a599b5de83fccb3bdaf29f4. Applied spacing, contrast, grouped hierarchy, keyboard state, reduced motion and batched desktop/mobile verification principles while preserving the user's pinned aesthetic. No remote skill launcher or downloaded binary was executed; this is source guidance, not an installed magic image-transfer tool.

Stage data uses two bounded public queries per catalogue load rather than41individual queries. No partial-success truncation. Programme error is represented as unknown/null, not zero published races. Stage filters combine sport/scope/month/status/programme/search; months include events that overlap month boundaries. Russia and international scopes never inferred from country labels. A stage may have only dates; qualification/final and cancelled records are accounted for without claiming final total starters.

Stage detail groups original race records by day, retains /race-center/{id}, links actual programme sources separately from the overall stage source, includes ICS and nearby stages within the same sport/scope. The source verification timestamp of a stage is not all race timestamps. Notes remain visible in an expandable block. No date, event or status mutation is part of this release.

Five real photo candidates from the user-supplied Olympteka galleries are mapped to existing venues across all four requested directions. Only original links and caption metadata are public until usage rights are reviewed. Research script retrieves bounded public originals and records exact byte hashes; it never generates/retouches faces, runs remote code, guesses author rights or publishes the images. Local research evidence is distinct from approved site assets. Credit alone is not permission. Do not call a candidate photo a champion portrait unless the result and individual identity are verified. stage-photo-approved.json is intentionally empty; the rendering gate requires identity, original preservation, license/evidence, author, dimensions and a local media path.

Prior generated mockups contain incorrect calendar examples; none are used as data or graphics for this release. Blocked FLGR proposals, blocked review-schema installation, old writer functions, Auth and media-upload flags are unchanged. Test and deployment evidence belongs in the PR after actual execution; file creation alone is not evidence of successful browser rendering.
